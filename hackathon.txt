Problem Statement 6:

Agentic MCP Gateway: Building an AI Agent That Orchestrates Third-Party APIs

via Model Context Protocol

Description:

The Model Context Protocol (MCP) is an emerging open standard that enables AI models to interact

with external tools, data sources, and APIs through a unified interface. While individual MCP server

implementations exist for popular services (GitHub, Slack, databases, etc.), there is no unified agentic

layer that can intelligently orchestrate multiple MCP connections to complete complex, multi-step

business workflows autonomously.

Your challenge is to build an Agentic MCP Gateway: an AI-powered orchestration layer that connects

to multiple third-party services via MCP servers, understands natural language workflow descriptions,

decomposes them into executable steps, and orchestrates cross-service operations while handling

errors, retries, and human-in-the-loop approvals.

Challenge Requirements:

1. MCP Server Integration: Build or configure MCP server connectors for at least four different

third-party services spanning different categories: a project management tool (e.g., Jira, Linear, or

Trello API), a communication platform (e.g., Slack or Discord API), a data/analytics service (e.g.,

Google Sheets, Airtable, or a SQL database), and a cloud/DevOps tool (e.g., GitHub, AWS, or

monitoring APIs). Each connector must implement the MCP specification for tool discovery,

invocation, and response handling.

2. Workflow Decomposition Engine: Build an LLM-powered planning agent that takes a natural

language workflow description (e.g., 'When a critical bug is filed in Jira, create a GitHub branch,

notify the on-call engineer in Slack, and update the incident tracker spreadsheet') and decomposes

it into a directed acyclic graph (DAG) of MCP tool calls with proper data flow between steps.

3. Execution Runtime: Implement a reliable execution runtime that: runs DAG steps in the correct

dependency order (with parallelism where possible), handles transient API failures with

configurable retry policies, supports human-in-the-loop approval gates for sensitive operations

(e.g., deploying code, sending external communications), and maintains an execution log with full

observability.

4. Context Management: Implement efficient context management so the agent can: maintain

conversation state across multi-turn interactions, pass output data from one MCP tool call as input

to subsequent calls, and handle large payloads (e.g., file attachments, long API responses)

through summarization or chunking.

5. Security and Access Control: Implement a permission model where: each MCP connection

has scoped credentials, the agent cannot escalate its own permissions, sensitive operations

require explicit user confirmation, and all API calls are logged for audit purposes.

Suggested Datasets:

Mock API servers for each integration category (provided as Docker containers), sample workflow

definitions in natural language, test scenarios with expected outcomes, and an MCP specification

reference implementation.
